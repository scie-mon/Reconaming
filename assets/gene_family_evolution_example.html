An illustrative evolutionary history

How does gene family evolution work?

A simplified, fictitious history of a multigene family, beginning with one gene in a single ancestral species.

Reading the diagrams: the species tree and gene tree are shown side by side. By default, colours identify species, not gene families or event types. The diagrams show topology only: horizontal distances do not represent elapsed time or substitutions. Unlabelled nodes with only one child are omitted from the drawings, but retained in the original Newick strings available below each tree.

Gene-tree controls: both display switches apply globally. Changing either switch in any panel updates all gene-tree panels and synchronises their switches. “Highlight duplication nodes” marks visible duplications with filled orange diamonds and the hidden duplication known from the stipulated history with a hollow, dashed diamond. “Purple non-duplication branches” replaces species colours in the gene trees and displays tip labels in a neutral colour. In this mode, each horizontal branch is coloured according to the node it leads into: branches entering visible duplication nodes are orange; all other branches, including those entering the hidden duplication, are purple. Vertical connectors use the colour assigned to the node they connect. Hidden-duplication annotations change the markers only, not the branch colours. Event labels reflect the constructed history, including the Gene5/Gene6 duplication retained through subsequent losses and the relabelling of the surviving genes as Gene3. These labels are annotations, not results inferred by GeneRax. Species-tree colours remain unchanged.

Large multigene families, such as chemoreceptors, have histories shaped by numerous successive speciation and duplication events. Encoding their full phylogenetic topology in numeric gene identifiers is therefore impractical, especially when the input dataset changes or expands as new sequence data become available. Such identifiers can reasonably represent only the immediate level of nested orthology.

Given a reconciled gene-family phylogeny, duplication nodes naturally define the boundaries of orthology groups (orthogroups).

14A nested naming example

Within a predefined, fixed taxonomic scope (for example, a particular genus), we can identify the first speciation node in each ancestral gene lineage and use these nodes to define “ParentGroups” as the starting points of nested orthogroups.

In this scheme, duplication nodes act as orthogroup boundaries: genes are assigned to the same orthogroup if the paths connecting them do not cross a duplication node. This boundary-based approach is particularly useful because inferred phylogenies are probabilistic estimates rather than established truths, and node-support values express confidence in the inferred relationships. Because declaring orthology is the more restrictive claim, the conservative approach is to treat an inferred speciation node as a non-boundary only when its support exceeds a chosen threshold. Boundaries therefore include both duplication nodes and insufficiently supported non-duplication nodes.
